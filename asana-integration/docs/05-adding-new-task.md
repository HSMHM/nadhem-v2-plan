# 05 — كيف تضيف مهمة جديدة لاحقاً

هذا الدليل يشرح بالضبط كيف تتعامل مع المنظومة عندما تحتاج لإضافة عمل جديد بعد الإطلاق الأول. ثلاث حالات شائعة:

| الحالة | المثال |
|---------|--------|
| **(أ) تطوير رئيسي جديد** | تطوير 16، 17، 200... كل واحد له مهمة في أسانا + 4 مراحل + مهام تفصيلية |
| **(ب) مهمة تفصيلية جديدة لتطوير موجود** | إضافة `101.3.9` (مهمة تنفيذ جديدة) داخل تطوير 101 |
| **(ج) تعديل مهمة موجودة** | تغيير وصف، فترة، أو نقل تطوير من P2 إلى P1 |

---

## 🛡️ القاعدة الذهبية — لا تخسر تعديلاتك

عند إعادة تشغيل `generate-fad-jsons.js` بدون أي flag، السكربت **يكتب فوق كل ملفات JSON الموجودة** ويفقد أي تعديلات قمت بها من تبويب "محاكاة أسانا" في React.

### استخدم دائماً `--only-missing` لحماية تعديلاتك:
```bash
cd asana-integration/scripts
node generate-fad-jsons.js --only-missing
```
هذا الـ flag يولّد فقط الملفات غير الموجودة — تعديلاتك السابقة لن تُلمَس.

### أو حدّد التطوير المعني فقط:
```bash
node generate-fad-jsons.js --dev=200          # ولّد كل ملفات DEV-200 (يكتب فوقها)
node generate-fad-jsons.js --dev=200 --only-missing   # ولّد ما لم يكن موجوداً فقط
```

### الخطوة 2 — صنّفه في **مكانَين** (هذا حرج!)

#### 2.أ في `asana-integration/scripts/classification.js`:
```js
export const CLASSIFICATION = {
  // ... القائمة الموجودة
  16: { type: 'new', section: 'add', interfaces: ['admin','user','api'] },
};
```

#### 2.ب في `nadhem-execution-plan/src/data/asanaClassification.js` (نسخة مطابقة):
```js
export const CLASSIFICATION = {
  // ... القائمة الموجودة
  16: { type: 'new', section: 'add', interfaces: ['admin','user','api'] },
};
```

> ⚠️ **يجب أن يبقى الملفان متطابقَين دائماً.** الأول يستخدمه السكربت، الثاني يستخدمه تطبيق React.

#### كيف تختار `type` و `section`؟
- **`new` + `section: 'add'`** — إذا كانت الخاصية **غير موجودة** في `saas-events-frontend` (راجع [`docs/01-saas-events-frontend-features.md`](./01-saas-events-frontend-features.md))
- **`change` + `section: 'mod'`** — إذا كانت الخاصية **موجودة** ونعدّل عليها

#### كيف تحدّد `interfaces`؟
| الواجهة | متى تختارها |
|---------|-------------|
| `admin` | يمس Admin SPA أو routes/admin.php أو لجان الإدارة |
| `user` | يمس صفحات المستخدم المحمية (/account, /dashboard, /register) |
| `public` | يمس الواجهة العامة (السبير الزائر) |
| `api` | يحتاج endpoints جديدة أو معدّلة |

إذا كان النوع `change`، أضف في **كلا** الملفَين الـAS_IS:

في `classification.js` و `asanaClassification.js`:
```js
export const AS_IS_DESCRIPTIONS = {

  16: 'الوضع الحالي في النظام: (وصف الخصائص الموجودة في saas-events-frontend التي ستُعدَّل)',

```

> راجع [`01-saas-events-frontend-features.md`](./01-saas-events-frontend-features.md) لاستخراج الأسماء التقنية الصحيحة (Controllers, Services, ...).

### الخطوة 4 — ولّد ملفات FAD JSON للتطوير الجديد فقط

```bash
cd asana-integration/scripts
node generate-fad-jsons.js --dev=16
```

النتيجة:
- `fad-jsons/main/FAD_DEV-16_v1.0.json` ← ملف رئيسي جديد
- `fad-jsons/subtasks/FAD_DEV-16.1.1_v1.0.json` ← لكل مهمة تفصيلية
- ... وهكذا

> 💡 لو خشيت من الكتابة فوق ملفات أخرى: استخدم `--dev=16 --only-missing`. لكن مع `--dev=` السكربت لا يلمس بقية التطويرات أصلاً.

### الخطوة 5 — راجع وعدّل في تبويب "محاكاة أسانا"

```bash
cd nadhem-execution-plan
npm run dev
```
ثم افتح المتصفح → تبويب "محاكاة أسانا" → "شجرة المهام":
- ابحث عن `DEV-16` (أو رقم تطويرك)
- افتح البطاقة، عدّل أي حقل (`_asana_name`, `_asana_notes`, الواجهات، قصة المستخدم...)
- اضغط **"حفظ التغييرات"** — التعديل يحفظ مباشرة في ملف JSON


## (ب) إضافة مهمة تفصيلية جديدة لتطوير موجود

مثال: تريد إضافة مهمة `101.3.9` (مهمة تنفيذ جديدة) داخل DEV-101.

### الخطوة 1 — أضف المهمة في المصفوفة المناسبة في `developments.js`
افتح dev 101، ثم في المصفوفة المناسبة (`implementation` لهذا المثال):
```js
implementation: [
  // ... المهام الموجودة (101.3.1 إلى 101.3.8)
  { id: '101.3.9', task: 'مهمة جديدة وصفها هنا', duration: '1 يوم' },
],
```

### الخطوة 2 — استخدم `--only-missing` لحماية تعديلاتك

```bash
cd asana-integration/scripts
node generate-fad-jsons.js --dev=101 --only-missing
```

النتيجة:
- ✅ يولّد ملف جديد `FAD_DEV-101.3.9_v1.0.json`
- 🛡️ لا يلمس الـ22 ملف فرعي السابق لـ DEV-101 (لو عدّلت أياً منها سابقاً)
- 🛡️ لا يلمس الملف الرئيسي `FAD_DEV-101_v1.0.json`

### الخطوة 3 — راجع وعدّل في تبويب "محاكاة أسانا"
ابحث عن `101.3.9` تحت تطوير 101 → مرحلة التنفيذ.

### الخطوة 4 — ارفع للأسانا
```bash
node push-to-asana.js
```

> ✅ السكربت يضيف فقط المهمة الفرعية الجديدة `101.3.9` تحت حاوية "تنفيذ" الموجودة لـ DEV-101 في أسانا، دون إعادة إنشاء أي شيء.

## (ج) تعديل مهمة موجودة

### السيناريو 1 — تعديل النص (الاسم/الوصف/الواجهات/...)
**أبسط طريقة:** افتح تبويب "محاكاة أسانا" → "شجرة المهام" → افتح البطاقة → عدّل الحقول → "حفظ التغييرات".

> ⚠️ **لكن هذا التعديل ينعكس فقط على ملف FAD JSON على القرص — وعلى ما سيُرسَل للأسانا في المرات القادمة من السكربت. المهام التي أُنشئت في أسانا سابقاً لن تتحدّث تلقائياً.**

#### إذا كانت المهمة لم تُرفع بعد:
ستُنشأ بالقيم الجديدة عند `node push-to-asana.js`.

#### إذا كانت المهمة قد رُفعت سابقاً:
خياران:
1. **يدوياً في أسانا** — افتح المهمة في أسانا وعدّل الاسم/الوصف
2. **آلياً (يحتاج توسعة):** السكربت الحالي لا يحدّث مهام أسانا الموجودة. لو احتجت ذلك، أخبر الوكيل بإضافة `--update` flag للسكربت يستخدم `tasks.updateTask()` بناءً على `.asana-state.json`.

### السيناريو 2 — تغيير الأولوية (`quarter`)
عدّل `quarter` في `developments.js` ثم:
```bash
# لو كانت الأولوية تؤثر على feature_id (مثل P1→P2):
node generate-fad-jsons.js --dev=<id>   # تجدّد ملف JSON بالأولوية الجديدة
```
> 💡 سيُكتب فوق الملف — لو لديك تعديلات يدوية، استخدم `--only-missing` لكن الأولوية القديمة ستبقى. الأفضل: عدّل `priority` يدوياً من تبويب محاكاة أسانا.

### السيناريو 3 — تغيير التصنيف (إضافة → تعديل أو العكس)
هذا تغيير جوهري:
1. عدّل في **كلا** ملفَي `classification.js` و `asanaClassification.js`
2. `node generate-fad-jsons.js --dev=<id>` (سيُكتب فوق الملف بالـrequest_type الجديد و القسم الجديد)
3. لو كانت المهمة قد رُفعت لأسانا في القسم القديم، انقلها يدوياً للقسم الجديد، أو احذفها وأعد الإنشاء

## ملخّص أوامر سريعة

| المهمة | الأمر |
|--------|-------|
| توليد كل JSONs (يدمر التعديلات) | `node generate-fad-jsons.js` |
| توليد آمن للملفات الناقصة فقط | `node generate-fad-jsons.js --only-missing` |
| تطوير واحد كامل (يُكتب فوقه) | `node generate-fad-jsons.js --dev=16` |
| تطوير واحد بدون لمس الموجود | `node generate-fad-jsons.js --dev=16 --only-missing` |
| معاينة الرفع لأسانا | `node push-to-asana.js --dry-run` |
| رفع فعلي (يكمل من النقطة الأخيرة) | `node push-to-asana.js` |
| إعادة تعيين حالة الرفع | احذف `.asana-state.json` يدوياً |

## فحوصات قبل الرفع

✅ هل أضفت التصنيف في **كلا** ملفَي classification.js و asanaClassification.js؟
✅ هل `id` فريد ولم يُستخدم في تطوير سابق؟
✅ هل ولّدت الـJSON بـ `--dev=<id>` بعد الإضافة؟
✅ هل راجعت في تبويب "محاكاة أسانا" أن البطاقة تظهر بالشكل الصحيح؟
✅ هل شغّلت `--dry-run` قبل الرفع الفعلي للتأكد من الشجرة المتوقعة؟

## ماذا لو أخطأت ولم أنتبه؟

### كتبتُ فوق تعديلاتي بـ`generate-fad-jsons.js` بلا flag:
- لو لم تكن قد رفعت لأسانا بعد: ابدأ من جديد، عدّل الملف من تبويب محاكاة أسانا
- لو كنت قد رفعت: ملفات FAD على القرص الآن بالقيم الافتراضية، لكن مهام أسانا تحوي القيم القديمة المعدّلة. لا حل آلياً — إما تعديل يدوي في أسانا أو تكرار التعديلات في React app

### رفعت تطويراً مُصنَّفاً خطأ (إضافة بدل تعديل):
- يدوياً انقل المهمة في أسانا للقسم الصحيح
- صحّح التصنيف في الملفَين
- شغّل `node generate-fad-jsons.js --dev=<id>` لتحديث ملف JSON

### حذفت `.asana-state.json` بالخطأ:
- السكربت سيحاول إنشاء كل المهام من جديد → ستحصل على نسخ مكررة
- **الحل:** إما احذف كل المهام من أسانا وأعد البدء، أو أعد بناء `.asana-state.json` يدوياً (يحتاج جلب gids من API أسانا)
