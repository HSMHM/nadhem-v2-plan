# دراسة عميقة: تطبيق "دورة حياة الفعالية" على خصائص نَظِّم

> **الهدف:** استنباط القائمة الكاملة لخصائص نَظِّم (الموجودة + المُخطَّطة) وتصنيفها حسب دورة حياة الفعالية الفعلية للعميل (قبل/أثناء/بعد + إعدادات شاملة).
>
> **المنهجية:** استنباط من
> - 16 وحدة في `modules.js` + 8 لجان + 4 باقات
> - 17 تطويراً (4 عاجلة + 13 مخططة) في `developments.js`
> - أوصاف الوضع الحالي `AS_IS_DESCRIPTIONS` (9 تطويرات)
> - معرفة بأنظمة إدارة الفعاليات (Cvent / Eventbrite / Bizzabo)
> - تفاعل مدير المنتج

## 1. اللجان الثمانية وأدوارها

| اللجنة | المسؤولية الرئيسية | المراحل التي تخدمها |
|---|---|:---:|
| **التنظيمية** | إدارة الجدول، الجلسات، أماكنها، الإطلاق | قبل + أثناء |
| **العلمية** | المشاركون (متحدثون/مدراء جلسات/مستشارون/مقدمو أوراق وبرامج)، الجلسات الاستشارية، الأوراق العلمية، البرامج المصاحبة | قبل + أثناء + بعد |
| **اللوجستية** | المدعوون، التحضير، الفنادق، المواصلات، البطاقات | قبل + أثناء |
| **المالية** | الفواتير، المدفوعات، الباقات، الإيرادات، التقارير المالية | قبل + أثناء + بعد |
| **الرعايات** | باقات الرعاة، طلبات الرعاية، عقود الرعاة، ممثلي الرعاة | قبل + بعد |
| **المعارض** | الجهات العارضة، خريطة المساحات، الحجز، عقود العارضين | قبل + أثناء |
| **الإعلامية** | المحتوى، الأخبار، الحملات، التغطية (فيديو/صور)، النشر، **منصة التوقيع** بعد دمج الشراكات | قبل + أثناء + بعد |
| **الشراكات** *(تُلغى في P0)* | الشراكات، الاتفاقيات → ستنتقل إلى الإعلامية في بطاقة "منصة التوقيع" | قبل |

## 2. أنواع المستخدمين في النظام

### مستخدمو إدارة (Admin SPA)
- **مدير النظام (Super Admin)** — صلاحيات كاملة على جميع الفعاليات
- **مدير الفعالية (Event Owner)** — صلاحيات كاملة على فعالية واحدة
- **منسّقو اللجان (Committee Coordinators)** — صلاحيات على لجنة معينة (8 لجان)
- **مدير نجاح العملاء (CSM)** — وصول قراءة/مساعدة على فعاليات العميل

### مستخدمو الواجهة الخارجية (User-facing)
- **حاضر عام (Attendee)** — يسجّل حضوره، يحصل على بطاقة، يحضر جلسات
- **كبار الشخصيات (VIP)** — مدعوون بدعوة شخصية، خدمة مميزة
- **مشاركون علميون** *(موحَّدون بعد dev 101 — multi-role)*:
  - متحدث (Speaker)
  - مدير جلسة (Session Director)
  - مستشار (Consultant)
  - مقدم ورقة علمية (Paper Author)
  - مقدم برنامج مصاحب (Workshop Presenter)
- **عارض (Exhibitor)** — يحجز مساحة ويعرض منتجاته
- **راعي (Sponsor)** + **ممثل الراعي** + **موظفو الراعي**
- **شريك (Partner)** *(يُدمج في "منصة التوقيع")*

### مستخدمو الزوار (Public)
- **زائر الموقع** — يتصفح صفحة الفعالية الخارجية، يسجّل، يحجز

## 3. تصنيف الخصائص حسب دورة حياة الفعالية

### 🟢 قبل الفعالية (Pre-event)

كل ما يحدث **بين قرار إقامة الفعالية وحتى لحظة فتح الأبواب**.

#### A. إعداد الفعالية (Event Setup)
- إنشاء فعالية جديدة (الاسم، التواريخ، الموقع، الوصف، الشعار، الألوان)
- اختيار باقة + تفعيل الوحدات المضمَّنة فيها
- إعدادات اللغة (عربي/إنجليزي/ثنائي)
- إعدادات المنطقة الزمنية والعملة
- ربط نطاق مخصص (Custom Domain) أو نطاق فرعي افتراضي
- نسخ من فعالية سابقة (Clone Event)

#### B. الواجهة الخارجية للزوار (Public Site)
- بناء صفحة الفعالية العامة (الواجهة الخارجية)
  - الرئيسية (Hero, Countdown, About)
  - **قسم المتحدثين** (شبكة/قائمة/بطاقات — قوالب متعددة بعد dev 6)
  - **قسم الجدول** (timeline/grid)
  - **قسم الرعاة** (باقات الرعاية مع شعاراتهم)
  - **قسم العارضين** (شبكة مع روابط)
  - **قسم خريطة المعرض التفاعلية** (يختار العارض مساحته من الخريطة → يسجّل → يدفع بعد الموافقة) — راجع I
  - **قسم البرامج المصاحبة (الورش)**
  - قسم الشركاء (في "منصة التوقيع" بعد الدمج)
  - قسم الموقع والوصول (خريطة، فنادق قريبة)
  - قسم التواصل (نموذج اتصال)
  - الأسئلة الشائعة (FAQ — مولّدة بـAI بعد dev 14)
- **تخصيص القائمة العلوية** (Top Navigation):
  - إضافة/تعديل/حذف عناصر القائمة
  - ترتيب العناصر بالسحب والإفلات
  - ربط كل عنصر بقسم/صفحة/رابط خارجي
  - أيقونات اختيارية لكل عنصر
- **تخصيص القائمة السفلية** (Footer):
  - أعمدة قابلة للتخصيص (روابط سريعة، تواصل، وسائل تواصل، حقوق النشر)
  - شعارات الجهات الراعية في الفوتر
- **إضافة صفحات إضافية** (Custom Pages):
  - إنشاء صفحات مخصصة بعنوان + محتوى نصي + وسائط
  - ربطها بالقائمة العلوية أو السفلية
  - رابط مخصص (slug) لكل صفحة
  - توليد محتواها بالذكاء الاصطناعي (بعد dev 14)
- اختيار **الثيم الخارجي** (Theme 1 أو Theme 2 بعد dev 102)
- محرر السحب والإفلات لترتيب الأقسام (بعد dev 6)
- تفعيل/إخفاء أقسام حسب الباقة

#### C. التسجيل والباقات (Registration & Pricing)
- إنشاء باقات تسجيل (مجانية/مدفوعة)
- **نموذج التسجيل الموحَّد** بعد dev 101:
  - "مشارك" = حضور أو VIP
  - فئات متغيرة (عنوان + وصف + سعر) لكل نوع
- نماذج تسجيل ديناميكية بحقول قابلة للتخصيص
- شروط وأحكام إلزامية
- بوابات الدفع (مفعّلة)
- إيصالات تلقائية للمدفوعات
- حالات التسجيل (مسجّل / تم الدفع / مؤكَّد / مرفوض)
- التسجيل عبر **النفاذ الوطني** (بعد dev 5) — إعداد وتفعيل لكل منظم
- إغلاق التسجيل تلقائياً عند الوصول للسعة القصوى

#### D. إدارة المشاركين العلميين (Scientific Participants)
*موحَّدون تحت "المشاركين" بعد dev 101 — multi-role*

##### المتحدثون (Speakers)
- إضافة متحدث (يدوياً / بدعوة)
- بيانات: الاسم، السيرة، الصورة، روابط التواصل، التخصص
- إرسال دعوة تحدّث (Speaker Invitation)
- موافقة/اعتذار من المتحدث
- ربط المتحدث بجلسة/جلسات
- لوحة المتحدث الشخصية (يرفع عرضه التقديمي، يرى جدوله)
- قوالب رسائل للمتحدثين

##### مدراء الجلسات (Session Directors / Moderators)
- تعيين مدير جلسة لكل جلسة
- صلاحيات إدارية على الجلسة (تقييم، أسئلة، وقت)
- إشعارات قبل الجلسة بدقائق

##### المستشارون (Consultants) + الجلسات الاستشارية
- قائمة المستشارين وتخصصاتهم
- جدولة جلسات استشارية (1:1) مع وقت محدد
- حجز موعد مع المستشار من الواجهة الخارجية
- تأكيد الحجز + تذكيرات
- ملاحظات المستشار بعد الجلسة

##### مقدمو الأوراق العلمية (Paper Authors)
- بوابة استقبال الأوراق العلمية
- نموذج تقديم ورقة (الموضوع، الملخص، الكلمات المفتاحية، الملف PDF)
- **معايير تقييم مخصصة** (5-10 معايير لكل ورقة)
- تعيين محكّمين (Reviewers) لكل ورقة
- حالات الورقة (مقدَّمة / قيد التقييم / مقبولة / مرفوضة / تحتاج تعديل)
- ربط الورقة بجلسة بعد القبول
- شهادة قبول الورقة
- نشر ملخصات الأوراق المقبولة على الموقع

##### مقدمو البرامج المصاحبة (Workshop Presenters)
- إضافة برنامج مصاحب (ورشة عمل / دورة مصغّرة)
- بيانات: العنوان، الوصف، المدة، السعة، الجمهور المستهدف
- ربط بمقدّم برنامج
- نموذج تسجيل خاص بالبرنامج
- شهادات حضور برنامج مصاحب (مختلفة عن شهادة الفعالية العامة)
- جدولة الورش بدون تعارض

#### E. إدارة الجلسات (Sessions Management)
- إنشاء جلسة (عنوان، وصف، نوع، تاريخ، وقت بدء، مدة، مكان)
- ربط بمتحدثين + مدير جلسة
- تحديد سعة الجلسة (Capacity)
- جلسات متوازية في قاعات مختلفة (Tracks/Rooms)
- جلسات افتراضية (مع رابط Zoom)
- جلسات هجينة (حضوري + افتراضي)
- نشر الجدول على الواجهة الخارجية
- تصدير الجدول PDF/Excel
- تنبيهات تعارض الجداول

#### F. إدارة أماكن القاعات (Venues/Rooms)
*انتقلت إلى التنظيمية بعد dev 103 — تشمل كل أنواع الجلسات*
- إنشاء قاعات (الاسم، السعة، التجهيزات، الموقع داخل المبنى)
- خريطة المبنى (طوابق، قاعات)
- ربط القاعات بـ:
  - الجلسات العلمية الرئيسية
  - **الجلسات الاستشارية** (قاعات/طاولات استشارية مخصصة)
  - **البرامج المصاحبة (الورش)** (قاعات تدريبية)
  - الجلسات الجانبية والاجتماعات
- تجنّب تعارض الحجوزات بين كل أنواع الجلسات

#### G. الجدول العام (Event Schedule)
*انتقل إلى التنظيمية بعد dev 103*
- بناء الجدول الزمني الكامل للفعالية
- تنظيم متعدد المسارات (Tracks)
- استيراد/تصدير الجدول
- مشاركة الجدول مع الحاضرين قبل الفعالية

#### H. إدارة الرعاية والرعاة (Sponsorships)
- إنشاء **باقات رعاية** (بلاتينية، ذهبية، فضية... + مزايا كل باقة)
- نشر باقات الرعاية على الموقع
- بوابة طلب رعاية (Sponsor Inquiry Form)
- إدارة طلبات الرعاية (موافقة/رفض)
- اتفاقية رعاية + توقيع إلكتروني (بعد dev 4)
- ربط الراعي + ممثله + موظفيه
- إدارة شعارات الرعاة + ترتيبها حسب الباقة
- نشر الرعاة على الواجهة + بطاقاتهم

#### I. إدارة المعارض + خريطة المعرض التفاعلية (Exhibition Management)
*خاصية محورية قبل الفعالية — تربط الواجهة الخارجية بالمنظم وبالعارض في مسار موحّد*

- إنشاء معرض مصاحب (الاسم، التواريخ، الموقع)
- **خريطة المساحات التفاعلية** (بعد dev 3):
  - رسم مساحات المعرض (Booths) على خريطة بصرية
  - تحديد أحجام المساحات وأسعار كل حجم
  - حالات لحظية لكل مساحة (متاحة / مطلوبة / محجوزة / مباعة)
- **مسار العارض الكامل (End-to-End):**
  1. زيارة الواجهة الخارجية → فتح خريطة المعرض
  2. تصفّح المساحات المتاحة بصرياً
  3. اختيار مساحة → تعبئة بيانات الجهة العارضة
  4. التسجيل + إرفاق المستندات
  5. **انتظار موافقة المنظم** (الحالة: "مطلوبة")
  6. عند الموافقة → إشعار بالقبول + رابط الدفع
  7. **الدفع المباشر** → تثبيت الحجز (الحالة: "مباعة")
  8. توقيع عقد العارض إلكترونياً (بعد dev 4)
- إدارة الجهات العارضة (Exhibitors) — قائمة، تفاصيل، عقد، موظفون
- اختيار العارض لمساحته من الخريطة
- شهادات مشاركة للعارضين

#### J. إدارة الدعوات (Invitations)
- قائمة المدعوين (إضافة فرديّة / استيراد Excel)
- أنواع الدعوات: حضور، تحدّث، شراكة، رعاية، عرض (مع dev 12)
- إرسال دعوة عبر بريد/SMS/واتساب
- **دعوات كبار الشخصيات (VIP)**:
  - تسجيلهم يتم **من خلال مدير النظام** (لا تسجيل ذاتي)
  - إرسال دعوة شخصية مخصصة لكل VIP
  - متابعة حالة الموافقة بشكل فردي
  - خدمة مميزة وتجهيزات خاصة (بطاقة VIP، صف خاص، إلخ)
- **الدعوات التفاعلية** (بعد dev 12):
  - زر قبول/اعتذار من داخل الدعوة
  - إضافة ملاحظات/سبب الاعتذار
  - تتبع حالة الدعوة (مرسلة / مفتوحة / مقبولة / مرفوضة / منتهية)
- لوحة متابعة الدعوات (للمنظم) مع فلاتر
- تذكيرات تلقائية قبل الموعد
- إشعارات لحظية للمنظم عند تفاعل المدعو

#### K. التحضير (Pre-arrival Setup)
- تجهيز قائمة الحضور النهائية
- إعداد قوالب البطاقات (انظر قسم Q)
- توليد QR Codes للحضور
- إرسال **بطاقة الدعوة الرقمية** قبل الفعالية مع QR
- اختبار أجهزة الـKiosks (بعد dev 8)
- ضبط الأجهزة في الموقع

#### L. التواصل والتسويق (Communications & Marketing)
- **إدارة الحملات الإعلانية** (مهمة اللجنة الإعلامية):
  - إنشاء حملة (عنوان، رسالة، جمهور مستهدف، تاريخ)
  - قنوات: SMS / بريد إلكتروني / واتساب
  - استهداف فئات (كل المسجلين / VIP / متحدثون / عارضون / إلخ)
  - جدولة الإرسال
  - إحصاءات (وصول، فتح، نقر)
- نشرات بريدية (Newsletters)
- إشعارات تلقائية عند:
  - التسجيل
  - تأكيد الدفع
  - أسبوع قبل الفعالية
  - يوم قبل الفعالية
  - بعد الفعالية (شكر + تقييم)

#### M. إدارة الأخبار والمحتوى (Content Management)
- نشر **أخبار الفعالية** قبل وأثناء (مهمة الإعلامية)
- إضافة صور/فيديوهات (Gallery)
- ربط بحسابات السوشيال ميديا
- مشاركة المحتوى عبر منصات التواصل

#### N. منصة التوقيع (حجز موعد توقيع)
*بطاقة "منصة التوقيع" داخل اللجنة الإعلامية — بعد dev 103*

**الفكرة:** تتيح المنصة لأي جهة (سواء كانت مشاركة في الفعالية أم لا) **حجز موعد توقيع رسمي على هامش الفعالية** مع جهة أخرى — يستثمر المنظِّم البيئة الإعلامية للفعالية لإجراء التوقيعات والإعلانات.

- إنشاء حجز موعد توقيع (التاريخ، الوقت، القاعة/الجناح)
- بيانات الجهة الحاجزة (الاسم، الممثل، التواصل)
- **بيانات الطرف الآخر** (الجهة التي ستُوقَّع معها) — تُحدَّد عند إنشاء الحجز
- نوع التوقيع (عقد، مذكرة تفاهم، شراكة، إلخ)
- جدول مواعيد التوقيعات داخل الفعالية
- إشعارات للأطراف قبل الموعد
- توثيق ما تم توقيعه + ربط بتغطية إعلامية لاحقة

#### N+. التوقيع الإلكتروني (E-Signature Integration)
*خدمة منفصلة عبر مزوّدي توقيع رقمي — اختيارية*

**الفكرة:** تكامل مع مزوّدي خدمات التوقيع الرقمي المعتمدة (مثل توقيع الرسمي، Adobe Sign، DocuSign) — لتوقيع المستندات إلكترونياً عن بُعد.

- ربط مع مزوّد توقيع رقمي (إعداد API key)
- يُستفاد منها لتوقيع:
  - عقود الرعاة (قبل أو بعد الموافقة)
  - عقود الجهات العارضة
  - أي مستند يحتاج توقيعاً رسمياً
- إرسال المستند للطرف الآخر
- متابعة حالة التوقيع
- أرشيف رقمي للمستندات الموقَّعة

> **الفرق المهم:**
> - **منصة التوقيع (N)** = حجز قاعة/موعد لحفل توقيع داخل الفعالية (event)
> - **التوقيع الإلكتروني (N+)** = خدمة رقمية لتوقيع المستندات عن بُعد (digital service)

#### O. النماذج والاستبيانات (Forms & Surveys)
- بناء **نماذج مخصصة** بمختلف أنواع الحقول (نصي، اختيار، Yes/No، تحميل ملف، تقييم نجمي، تاريخ، ...)
- منطق شرطي بين الحقول (Conditional Logic)
- نشر النموذج مع رابط مشاركة قابل للتضمين
- جمع الإجابات في لوحة عرض مركزية + فلاتر
- تصدير الإجابات Excel/CSV/PDF
- **استخدامات النماذج:**
  - استبيانات قبل الفعالية (توقعات الحاضرين، الاهتمامات)
  - استمارات تسجيل مخصصة (إن لم يكفِ نموذج التسجيل القياسي)
  - نماذج تقديم الأوراق العلمية
  - نماذج طلب الرعاية
  - نماذج التواصل والاقتراحات
  - **استبيانات بعد الفعالية** (تقييم الجلسات، رضا الحاضرين، NPS)
- إحصاءات لحظية على نسبة الاستجابة

#### P. إدارة المستخدمين والصلاحيات
- إنشاء/تعديل/حذف مستخدمي إدارة
- تعيين أدوار (Super Admin / Event Owner / Committee Coordinator / CSM)
- تعيين لجان لكل منسّق
- صلاحيات دقيقة (Permissions per Module)
- سجل الدخول لكل مستخدم

#### Q. قوالب البطاقات (Badge Templates)
- مكتبة قوالب جاهزة + قابلة للتخصيص لكل نوع مستخدم
- تخصيص: شعار، ألوان، QR، صورة شخصية، حقول ديناميكية
- معاينة قبل الطباعة
- اختيار حجم البطاقة (A6/A5/Custom)

#### R. قوالب الشهادات (Certificate Templates)
- مكتبة قوالب لأنواع متعددة من الشهادات
- تخصيص الخلفية، التوقيعات، الشعار، الألوان
- متغيّرات ديناميكية (`{{name}}`, `{{event_name}}`, `{{date}}`)
- معاينة + تصدير PDF
- توليد بالذكاء الاصطناعي بعد dev 14

#### S. قوالب الواجهة الخارجية
*بعد dev 6 — قوالب الواجهة v2 + السحب والإفلات*

- محرر بنائي بالسحب والإفلات لترتيب الأقسام
- معاينة مباشرة

#### T. قوالب الرسائل (Message Templates)

- قابلة للتعديل لكل فعالية
- متغيّرات ديناميكية في النص

#### U. التكاملات (Integrations)

### 🔴 أثناء الفعالية (Live)

كل ما يحدث **يوم/أيام إقامة الفعالية نفسها** — من فتح الأبواب لإغلاقها.

#### A. التحضير في الموقع (Check-in / Onsite Registration)
- مسح **QR Code من البطاقة** (دخول سريع)
- التحقق من الهوية يدوياً (Backup)
- التسجيل في الموقع (Walk-in) — إن لم يُسجَّل مسبقاً
- اختيار نوع المشارك (حضور/VIP/متحدث/إلخ)
- طباعة بطاقة فورية
- **أجهزة الخدمات الذاتية (Kiosks)** بعد dev 8:
  - تحضير ذاتي
  - طباعة فورية للبطاقة
  - بدون انتظار في طوابير

#### B. استخدام قوالب البطاقات (مُجهَّزة سابقاً قبل الفعالية — راجع قسم "قبل > Q")
- استخدام البطاقات المُجهَّزة لكل نوع مستخدم (حاضر/VIP/متحدث/مدير جلسة/عارض/راعي/شريك)
- مسح QR للبطاقة لتسجيل الحضور وربطه بنوع المشارك

#### C. تطبيق الهواتف الذكية (Mobile App)
*بعد dev 9 — iOS + Android مخصص لكل فعالية*
- **الجدول الشخصي** (My Schedule)
- خريطة الموقع (Venue Map)
- بطاقتي + QR للمسح
- قائمة المتحدثين + سيرتهم
- قائمة الجلسات + التسجيل فيها
- قائمة الورش (البرامج المصاحبة)
- قائمة الرعاة + العارضين + خريطة المعرض
- **الإشعارات الفورية** (Push Notifications):
  - تذكير بجلسة قريبة
  - تغيير في الجدول
  - رسائل من المنظم
  - عروض من الرعاة/العارضين
- مسح QR للحضور في الجلسات
- التواصل مع مشاركين آخرين (Networking) — مستقبلاً

#### D. حضور الجلسات (Session Attendance)
- مسح QR عند دخول الجلسة (Track attendance per session)
- إحصاءات الحضور لحظياً (للمنظم)
- إغلاق الجلسة تلقائياً عند الوصول للسعة
- لوحة مراقبة لمدير الجلسة:
  - عدد الحاضرين
  - الوقت المتبقي
  - إدارة الأسئلة (Q&A — مستقبلاً)

#### E. حضور الورش (Workshop Attendance)
- تسجيل حضور منفصل لكل ورشة (لاحتساب شهادة منفصلة)
- تتبع الحاضرين لكل ورشة
- شهادة مرتبطة بالحضور الفعلي

#### F. الجلسات الاستشارية (Consultation Sessions)
- جدولة لحظية في الموقع
- تأكيد المستشار للحضور
- ملاحظات بعد الجلسة

#### G. لوحة مؤشرات لحظية (Real-time Dashboard)
*بعد dev 10 — لوحة لكل لجنة*
- التنظيمية: عدد الحضور، نسبة الجلسات المكتملة
- العلمية: حضور المتحدثين، حضور الجلسات الاستشارية، الأوراق المعروضة
- اللوجستية: حالة المدعوين، الموجودون فعلاً، الفنادق، النقل
- المالية: الإيرادات حتى اللحظة، المعاملات المكتملة
- الرعايات: مشاركة الرعاة، تواجد ممثليهم
- المعارض: إقبال الزوار على المساحات (يحتاج تتبع IoT لاحقاً)
- الإعلامية: نشاط الحملات، تفاعل السوشيال

#### H. التغطية الإعلامية (Live Coverage)
*مهمة اللجنة الإعلامية*
- التقاط صور لحظية ورفعها للـ Gallery
- بث مباشر (Live Streaming) — إن كانت الجلسات افتراضية/هجينة
- تحديثات السوشيال ميديا اللحظية
- تغطية الفيديو
- مقابلات مع المتحدثين/الرعاة

#### I. الدعم اللحظي (Live Support)
- نقطة دعم في الموقع (Information Desk)
- شات live على التطبيق (مستقبلاً)
- إعادة طباعة بطاقات تالفة

#### J. تنفيذ مواعيد التوقيع (منصة التوقيع — تشغيل اليوم)
*المواعيد المحجوزة في القسم N من "قبل الفعالية" تُنفَّذ هنا*

- استقبال الجهات الحاجزة في موعدها
- تجهيز القاعة/الجناح (شعار، طاولة، خلفية إعلامية)
- التوثيق الإعلامي (صور، فيديو، بث)
- توقيع الأوراق رسمياً (يدوياً أو إلكترونياً إذا كان التكامل مفعّلاً)
- إعلان ما تم توقيعه (إن سمح الأطراف)
*بعد dev 103*
- عقود رعاية إضافية تُوقَّع في المعرض
- اتفاقيات شراكات تُبرم على هامش الفعالية
- توقيع رقمي فوري

#### K. الطوارئ والحوادث (Incident Management)
- تسجيل حوادث/مشاكل
- تخصيصها لمسؤول
- متابعة الحل

### ⚪ إعدادات وبنية شاملة (Cross-cutting)

البنود التي **تعمل في الخلفية عبر كل مراحل دورة الفعالية** ولا تركّز في مرحلة محددة.

#### A. الأمان والخصوصية
- HTTPS لكل الفعاليات
- مصادقة ثنائية (2FA) للإدارة
- موافقة GDPR على البيانات
- تشفير المعلومات الشخصية
- نسخ احتياطية يومية

#### B. التقارير الدورية للمنظم
- تقرير أسبوعي (تسجيل، إيرادات، تفاعل)
- تقرير شهري (شامل)
- تقرير ربع سنوي (مقارنة بالأهداف)
- تقرير سنوي (الإنجازات، نمو الاشتراكات)

#### C. سجل النشاط (Audit Log)
- كل تعديل + من قام به + متى
- سجل الدخول لكل مستخدم
- استرجاع نسخ سابقة (مستقبلاً)

> **ملاحظة:** البنود التالية كانت ضمن "Cross-cutting" سابقاً ونُقلت إلى **قبل الفعالية** لأنها فعلياً عمليات إعداد قبل بدء الفعالية:
> إدارة المستخدمين والصلاحيات • قوالب البطاقات • قوالب الشهادات • قوالب الواجهة الخارجية • قوالب الرسائل • التكاملات • الذكاء الاصطناعي • الباقات والوحدات • التخصيص البصري • اللغة والترجمة.

| **متحدث** | يستلم دعوة، يرفع عرضه، يرى جدوله | يقدّم جلسته، يرى أسئلة الجمهور | شهادة متحدث + تقييم جلسته |
| **مدير جلسة** | يطّلع على المتحدثين والوقت | يدير الجلسة (وقت/أسئلة/تقييم) | شهادة مدير جلسة |
| **مستشار** | جدول استشاراته + الحجوزات | يقابل المستشيرين + يكتب ملاحظات | شهادة مستشار + تقرير استشاراته |
| **مقدم ورقة** | يقدّم الورقة + يستلم نتيجة التحكيم | إن قُبلت: يعرضها في جلسة | شهادة قبول/تقديم ورقة |
| **مقدم برنامج (ورشة)** | يبني محتوى الورشة + يرى المسجلين | يقدّم الورشة + يحضّر الحاضرين | شهادة + تقييم الورشة |
| **راعي + ممثل + موظفون** | عقد، شعار، باقة، مواد ترويجية | تواجد ميداني، عقود إضافية | شهادة شكر + Leads + تقرير الرعاية |
| **عارض** | يحجز مساحة عبر الخريطة، يدفع، يجهز جناحه | يستقبل الزوار، يبيع، يجمع Leads | شهادة + Leads + تقرير المعرض |
| **زائر الموقع** | يتصفح الموقع + يفكّر في التسجيل | يتابع التغطية الإعلامية لحظياً | يقرأ خبر الختام + ينتظر الفعالية القادمة |

## 6. كل خاصية ومتطلباتها (CRUD + إعدادات + تقارير + قوالب)

> **القاعدة العامة لكل خاصية في النظام:**
>
> 1. **عرض القائمة (List)** — جدول مع فلاتر/بحث/فرز/ترقيم
> 2. **إضافة (Create)** — نموذج إدخال مع تحقق
> 3. **تعديل (Update)** — تعديل سجل قائم
> 4. **حذف (Delete)** — مع تأكيد + سجل (Soft delete)
> 5. **عرض التفاصيل (Detail)** — صفحة تفاصيل الكاملة
> 6. **استيراد/تصدير** — CSV/Excel للاستيراد، PDF/Excel للتصدير
> 7. **إعدادات** — قواعد عمل، حدود، خيارات افتراضية
> 8. **قوالب** — حيثما ينطبق (بطاقات، شهادات، رسائل)
> 9. **تقارير** — كل خاصية يجب أن تُولّد تقرير خاص
> 10. **سجل التغييرات** — Audit Log لكل عملية
> 11. **صلاحيات** — أي دور يستطيع ماذا (View/Create/Edit/Delete)

### أمثلة تفصيلية على تطبيق هذه القاعدة:

#### مثال 1: المتحدثون (Speakers)
| العملية | التفاصيل |
|---|---|
| القائمة | جدول: الاسم، التخصص، عدد الجلسات، حالة الدعوة، تاريخ الإضافة |
| فلاتر | حسب التخصص، الحالة، الجلسة المرتبطة |
| الإضافة | يدوياً / استيراد Excel / دعوة عبر بريد |
| الحقول | اسم، صورة، سيرة، تخصص، روابط سوشيال، رقم/بريد، نوع الحضور (حضوري/افتراضي) |
| التعديل | كل الحقول قابلة للتعديل |
| الحذف | Soft delete مع سبب |
| التفاصيل | كل البيانات + تاريخ الدعوة + الجلسات + ملاحظات |
| الاستيراد/التصدير | استيراد قائمة من Excel، تصدير القائمة لـExcel/PDF |
| الإعدادات | سياسة الموافقة (تلقائية/يدوية)، مدة صلاحية الدعوة |
| القوالب | قالب رسالة دعوة المتحدث، قالب بطاقة المتحدث، قالب شهادة |
| التقارير | تقرير المتحدثين الذين حضروا فعلاً، تقييم كل متحدث |
| السجل | من أضاف، من عدّل، متى |
| الصلاحيات | منسّق العلمية: كل الصلاحيات. المدير: قراءة |

#### مثال 2: الأوراق العلمية (Scientific Papers)
| العملية | التفاصيل |
|---|---|
| القائمة | جدول: عنوان الورقة، المؤلف، الحالة، عدد المحكّمين، التقييم النهائي |
| فلاتر | حسب الحالة (مقدَّمة/قيد التحكيم/مقبولة/مرفوضة)، التخصص، المؤلف |
| الإضافة | عبر بوابة عامة (بنوع المؤلف) أو يدوياً من المنسّق |
| الحقول | عنوان، ملخّص (250 كلمة)، كلمات مفتاحية، ملف PDF، السيرة، التخصص |
| التعديل | المؤلف يستطيع تعديل قبل الإغلاق، المنسّق دائماً |
| الحذف | حذف نهائي بإذن المنسّق |
| التفاصيل | كامل البيانات + المراجعات + تعليقات المحكّمين |
| الاستيراد/التصدير | تصدير ورقة كاملة PDF، تصدير قائمة Excel |
| الإعدادات | عدد المحكّمين لكل ورقة، معايير التقييم (مخصصة)، حدّ النجاح |
| القوالب | قالب قبول، قالب رفض، قالب طلب تعديل، قالب شهادة قبول |
| التقارير | تقرير الأوراق المقبولة/المرفوضة، تقرير المحكّمين، إحصاءات |
| السجل | كل تغيير حالة + من قام به |
| الصلاحيات | مؤلف: ورقته فقط. محكّم: الأوراق المعيّنة له. منسّق: كل شيء |

#### مثال 3: الجلسات الاستشارية (Consultation Sessions)
| العملية | التفاصيل |
|---|---|
| القائمة | جدول: المستشار، التخصص، الأوقات المتاحة، الحجوزات، الحالة |
| فلاتر | حسب المستشار، التخصص، اليوم، الحالة |
| الإضافة | المنسّق يضيف مستشاراً + جدولته |
| الحقول | اسم المستشار، تخصصه، الأوقات (slots)، المدة لكل استشارة، السعة |
| التعديل | تعديل الجدول، إلغاء slot |
| الحذف | إلغاء كامل لاستشارات مستشار |
| التفاصيل | جدول كامل + الحجوزات الحالية + تاريخ الاستشارات |
| الاستيراد/التصدير | تصدير جدول استشارات لـPDF |
| الإعدادات | المدة الافتراضية لكل استشارة، الحدّ الأقصى للحجز قبل المستشار، إشعارات |
| القوالب | قالب رسالة تأكيد الحجز، قالب تذكير، قالب إلغاء |
| التقارير | تقرير الاستشارات المنفذة، تقييم المستشارين، الإحصاءات |
| السجل | حجوزات + إلغاءات |
| الصلاحيات | المستشار: جدوله فقط. المنسّق: كل المستشارين |

*(نفس النمط يُطبَّق على باقي الخصائص: البرامج المصاحبة، المعارض، الرعايات، الدعوات، إلخ.)*

## 7. التطبيق المقترح في النظام

### الهدف:
بناء **عرض جديد في نَظِّم نفسه** (وليس فقط في خطة التنفيذ) يُظهر للمنظم خصائص النظام منظَّمة حسب دورة حياة فعاليته.

### الخيار A — Dashboard "دورة الفعالية" داخل نَظِّم
في لوحة المنظم، إضافة قسم رئيسي:

### الخيار B — قائمة جانبية مُعاد تنظيمها
بدل ترتيب القائمة الجانبية حسب اللجان فقط، يكون التبديل ممكناً بين:
- 🏛 **عرض حسب اللجان** (الحالي)
- 🎯 **عرض حسب دورة حياة الفعالية** (الجديد)

كل عرض يُعيد ترتيب نفس الخصائص بطريقة مختلفة.

### الخيار C — Widget في الصفحة الرئيسية
كروت سريعة في dashboard المنظم تظهر "ماذا يجب أن تفعله الآن؟" حسب موقع فعاليتك في الدورة:
- إذا تاريخ الفعالية > 30 يوماً → كروت "قبل" نشطة
- إذا < 30 يوماً → كروت "قبل" + تنبيهات استعداد لـ"أثناء"
- يوم الفعالية → كروت "أثناء" نشطة
- بعد الفعالية → كروت "بعد" نشطة

**القاعدة الذكية:** الكروت تتلوّن وتتغيّر حسب موقع الفعالية في الدورة الزمنية.

### الخيار D — Onboarding Wizard
عند إنشاء فعالية جديدة، **معالج (Wizard) من 4 مراحل**:
1. **قبل** → إعداد التسجيل، الجدول، المتحدثين، الرعاة
2. **أثناء** → اختيار طريقة التحضير (Kiosks/Manual)، إعداد التطبيق، اللوحات اللحظية
3. **بعد** → اختيار قوالب الشهادات، تجهيز استبيانات
4. **شامل** → الإعدادات العامة (لغة، عملة، تكاملات)

Cvent تستخدم نمطاً مشابهاً عند إعداد فعالية جديدة.

## 8. التوصيات النهائية

### الأولوية 1 (تأثير عاجل — منخفض الكلفة) ✨
- **الخيار C: Widget في الصفحة الرئيسية**
- يعطي قيمة بصرية فورية لكل منظم
- لا يعدّل البنية الحالية للنظام
- **الوقت المقدَّر:** 2-3 أيام تطوير

### الأولوية 2 (تأثير قوي — كلفة متوسطة)
- **الخيار D: Onboarding Wizard**
- خصوصاً للعملاء الجدد (فعّال جداً للـ onboarding)
- يسرّع من جاهزية الفعالية
- **الوقت المقدَّر:** 1-2 أسبوع

### الأولوية 3 (إعادة هيكلة كبيرة)
- **الخيار B: قائمة جانبية بعرضين**
- يحتاج دراسة UX عميقة
- قد يربك المستخدمين الحاليين
- **الوقت المقدَّر:** 3-4 أسابيع

### الأولوية 4 (مستقبلية)
- **الخيار A: Dashboard دورة الفعالية**
- إذا الـ Wizard نجح، نطوّره لـ Dashboard دائم

| **عدد الخصائص أثناء الفعالية** | ~30 خاصية |
| **عدد الخصائص بعد الفعالية** | ~25 خاصية (شهادات بأنواعها للمشاركين والمنظمين + التقارير + التقييمات + التغطية الختامية + Networking + الأرشفة + المالية الختامية) |
| **عدد الخصائص الشاملة** | 3 مجموعات فقط (الأمان، التقارير الدورية، سجل النشاط) |
| **اللجان التي تخدم كل المراحل** | العلمية + الإعلامية + المالية |
| **اللجان للمراحل المحددة** | الباقي يخدم 1-2 مرحلة |
| **أنواع الشهادات الكلية** | ~15 نوع (12 للمشاركين + 4+ للمنظمين والطاقم) |
